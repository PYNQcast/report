\section{Client Node Design}

\subsection{SoC Architecture}

The PYNQ-Z1 SoC integrates a dual-core ARM Cortex-A9 processing system (PS) with a programmable logic (PL) FPGA fabric on a single chip. 

\vspace{0.5em}

The Digital Differential Analysis (DDA) algorithm's repetitive per-column computation and fixed-point arithmetic lend themselves naturally to hardware implementation in the PL, where such operations can be executed far more efficiently than on a general-purpose CPU. 

\vspace{0.5em}

Custom IP blocks for the raycasting engine, HDMI pass-through, and BRAM controller were implemented in SystemVerilog and integrated into a Vivado block design alongside the necessary peripherals. The BRAM controller exposes an AXI interface to the PS, through which the map layout, player coordinates, and camera angle are written each game tick and consumed by the PL for rendering.

Existing IP blocks were used for the buttons to be used as input. Once the input is received, calculations are done on the PS to determine the new player position, these are written to the BRAM for rendering new frames and also sent to AWS to update the game state.

\subsection{Raycasting Engine Design}

The rendering pipeline is implemented entirely in synthesisable SystemVerilog, producing one column per clock cycle after an initial fill latency.  Key parameters are summarised in Table~\ref{tab:rayparams}.

\midrule

\AltRow Ray steps (max) & 64 \\

The raycasting engine uses the DDA algorithm to find the distance to the closest wall. For each vertical screen column, a ray is cast from the player's position in the direction determined by the camera plane. 

\vspace{0.5em}

As shown in Figure~\ref{fig:ray-miss}, stepping along the ray at fixed increments risks skipping over walls. Instead, DDA jumps from one grid boundary to the next by computing the distance to the nearest horizontal and vertical tile edge, advancing to the closer edge and repeating the process until it reaching a wall (Figure~\ref{fig:ray-hit}).

    \caption{Non-DDA Ray Projection}

\end{figure}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\linewidth]{images/ddaWallHit.png}
    \caption{DDA Ray Projection}
    \label{fig:ray-hit}
\end{figure}

\vspace{0.5em}

Once a wall tile is detected, the perpendicular distance of the wall to the camera plane is calculated using the formula:
\[perpWallDist = (sideDistx - deltaDistX)\]
this is illustrated in Figure~\ref{fig:dist-calc}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\linewidth]{images/distancecalc.png}
    \caption{Perpendicular Distance Calculation}
    \label{fig:dist-calc}
\end{figure}

With $perpWallDist$, the column height $L$ on the screen is calculated using the formula:
\[L = h/perpWallDist\]
Where $h$ is the height of the screen in pixels (240).

More distant walls produce shorter columns — naturally encoding perspective.




\subsection{Sprite and Texture Rendering}



\subsection{Pipeline Stages}

The raycaster executes as a free-running pipeline with no stalls under normal operation:

\begin{keyequation}
\[
t_{\text{col}} = \frac{\text{ray\_steps}_{\max}}{\text{f}_{\text{clk}}} = \frac{64}{100\times10^{6}} = 0.64\;\mu\text{s}
\]
\end{keyequation}

At 320 columns per frame this gives a theoretical frame time of $\sim$205\,$\mu$s, well within a 60\,fps budget (16.7\,ms).
